# QA Checklist

## Must-Haves

- Aspect ratio is 16:9.
- Background is clean, pure white.
- Xiaohei is present.
- Xiaohei performs the core action, not just decoration.
- No copying of old case compositions; a new metaphor is generated specifically for the current article.
- Visuals are absurd, creative, and interesting.
- Clean and sparse; the main subject takes up no more than 60% of the canvas.
- One image explains exactly one core structure.
- English annotations are few, short, and legible.
- Orange is used only for the main path, flows, or arrows.
- Red is used only for key points, warnings, issues, or outcomes.
- Blue is used only for supplementary notes, feedback, or system states.

## Failure Signals

If any of these occur, regenerate or edit locally:

- A category title like "Common Pitfalls / Workflow / System Architecture / Roadmap" appears in the top-left corner.
- Xiaohei looks like a mascot, sticker, emoji, or cute cartoon character.
- Visuals resemble a corporate PPT slide, course material, or standard flowchart.
- Too many elements, too many arrows, or too many nodes.
- Annotations turn into long blocks of explanation text.
- Background has paper texture, shadows, gradients, beige, or noise.
- Visuals contain actual UI screenshots or tech-heavy interfaces.
- English annotations have severe spelling errors or are illegible.
- The visual is too rigid and lacks an absurd metaphor.
- The composition is too similar to the old cases in `assets/examples/`.

## Iteration Methods

- Too generic: Make Xiaohei the active subject of the action; introduce a weird but fitting metaphor.
- Too complex: Remove nodes, keeping only one action and 3-5 short annotations.
- Too cute: Emphasize "deadpan, blank serious expression, not cute, not mascot".
- Too corporate/PPT-like: Remove titles, boxes, rigid grids, and excess arrows. Change to a hand-drawn scene.
- Too similar to old cases: Keep the core meaning, but replace the main object and Xiaohei's action.
- Text errors: Try local edits first; if there are many errors, regenerate and reduce the number of annotations.

## Delivery Standard

A high-quality illustration should make the reader think "that's a bit strange" at first, then understand the structure within 1 second.

If it looks like a textbook page instead of an absurd product sketch on blank paper, it fails.
